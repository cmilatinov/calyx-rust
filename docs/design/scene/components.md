# Components

Components are Legion ECS components with a reflected, type-erased side, so
the editor, scene files and project code handle them by type UUID. Lifecycle
hooks are opt-in traits that the scene runs only on the objects holding the
component.

Code: `crates/calyx_engine/src/component/` (`component.rs` for the traits and
`ComponentRef`), `crates/calyx_engine/src/class_registry.rs`,
`crates/calyx_engine/src/scene/hook_targets.rs`.

## Traits

- `Component` covers destroy, `draw_gizmos` and `can_disable`
  ([Component Enabled State](component-enabled-state.md)).
- `ComponentInstance`, generated by `#[derive(Component)]`, serializes and
  binds a component type-erased.
- `ComponentStart`, `ComponentUpdate`, `ComponentReset` and `ComponentHud` are
  separate lifecycle traits, opted into with `#[reflect(...)]`.
- The component registry (`ComponentRegistry`) keeps each hook as its
  reflected function (`ReflectComponentUpdate` and the others), not as a hook
  call on the registry's default prototype instance.

## Hooks

- Hooks are associated functions with no `self`. The scene runs each one only
  on the objects holding its component, skipping whole archetypes that lack
  it; an object gaining or losing the component during the pass is visited as
  it then is.
- Start, update and reset get `this: ComponentRef<Self>`, a typed handle to
  the object's own component, which stays in the ECS world while the hook
  runs, because the hook also gets `&mut Scene`.
- The hook reads and writes it with `this.read(ctx.scene, ..)` and
  `this.write(ctx.scene, ..)`. The stored component is the only copy, so
  writes through the handle and through `ctx.scene` apply at once and in call
  order, and after the hook removes or replaces its component the handle
  reaches nothing or the replacement.
- `ComponentHud::build_hud` only reads the scene, so it gets `this: &Self`
  directly. The HUD itself is in [HUD / Runtime UI Architecture](../hud-ui/architecture.md).
- `Scene::start`, `Scene::update` and `Scene::build_hud` skip the hooks of a
  disabled component.

## Built-in components

Transform, Camera, ThirdPersonCamera, CameraPath, Mesh, SkinnedMesh, Collider,
RigidBody, DirectionalLight, PointLight, SpotLight, AmbientLight, SkyLight,
Animator, Bone, ParticleSystem ([Particles](../rendering/particles.md)),
Terrain ([Terrain](../rendering/terrain.md)), Water
([Water](../rendering/water.md)), Foliage ([Foliage](../rendering/foliage.md)),
GrassField ([Grass](../rendering/grass.md)), GlobalPostProcessVolume,

([Post-Processing Architecture](../post-processing/architecture.md)), and the
network components in `net/component/` ([Networking](../net/networking.md)).

## Camera path

`ComponentCameraPath` (`component/camera_path.rs`) flies its object, usually a
camera, in play along a Catmull-Rom curve through the children of its `path`
object, in hierarchy order, easing between the children's rotations, over
`duration` seconds, `looping` or stopping at the last stop.

- Several objects can follow one path.
- Its gizmo draws while the follower, the path object or a stop is selected
  (`Gizmos::selected_object`).
- The curve math (`math::cubic_bezier`, `math::catmull_rom_to_bezier`,
  `math::catmull_rom`) is shared with `Gizmos::cubic_bezier` and
  `Gizmos::catmull_rom`.

## Post-process effect components

The effect components (`ComponentTonemap`, `ComponentBloom`,
`ComponentAmbientOcclusion`, `ComponentDepthOfField`, `ComponentColorGrading`,
`ComponentVignette`, `ComponentAntiAliasing`, `ComponentFog`,
`ComponentOutline` and `ComponentFogOfWar`, in `component/post_process/`) sit
beside a global or local volume on its game object and hold authoring data
only, save `ComponentFogOfWar::sight`, what a side sees, which game code sets
every frame and is never saved. A volume's `profile` references a
`PostProcessProfile` asset (`assets/post_process_profile/`) whose entries they
override, and the passes in `render/postprocess/` read them through
`PostProcessSettings`.
