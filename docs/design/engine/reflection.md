# Reflection

Runtime reflection lets the editor, scene files and project code reach types
they were not compiled against: fields by name, enums by variant, traits by
registered metadata. It drives the editor's inspectors.

Code: `crates/calyx_engine/src/reflect/` (`reflect.rs`, `type_info.rs`,
`type_registry.rs`, `trait_meta.rs`, `impls/`), `crates/calyx_engine_derive/`.

## Model

- The `Reflect` trait gives field access. `TypeInfo` describes structs,
  enums, lists, options and maps.
- A reflected enum's value reads its current variant and switches to a unit
  variant by name through `Reflect::as_enum` and `as_enum_mut`
  (`ReflectEnum`, generated by `#[derive(Reflect)]`). Each `EnumVariantInfo`
  carries its `#[reflect_attr]` attributes, such as a display `name`.
- `#[reflect_attr]` attributes carry editor metadata on types, fields and
  variants.
- `#[reflect_trait]` generates the metadata that registers a trait object for
  a type, and `#[reflect(...)]` on a type lists the traits it registers.

## Identity

- `TypeRegistry` keys types and trait metadata by type UUID
  (`#[derive(TypeUuid)]`, `#[uuid = "..."]`). The UUID identifies a type in
  saved data and registry lookups only.
- Every downcast, of a reflected value, a resource or trait metadata, checks
  the `TypeId`, so two types that share a name or a UUID never pass for each
  other. This is also why the project assembly must share the editor's engine
  build ([Project Assembly](../project/project-assembly.md)).

## Inspectors

Components get their inspector UI from `Reflect` and `TypeInfo`. A field or
list element whose enum has only unit variants and no type inspector of its
own is a dropdown of its variants, labelled by each variant's `name`
attribute or its name in title case; an enum with data-carrying variants
still shows its type name.
